# Несколько блюд в одном приёме пищи

Приём пищи — это событие: время, тип, аппетит, насыщение и самочувствие после еды. Внутри него может быть несколько блюд: суп, второе, напиток. У каждого блюда своя порция и пищевая ценность. Число приёмов пищи, интервалы между ними и вопрос «Как прошла еда?» относятся к приёму целиком: три блюда одного обеда остаются одним приёмом.

## Блюдо

| Поле | Что значит |
| --- | --- |
| Название и состав | Название блюда и то, из чего оно состоит (как распознано по фото или введено). Количества для состава не придумываются. |
| Порция | Масса поданной порции, г. |
| Съели | Доля поданной порции: всё, 75 %, 50 % или 25 %. |
| Ккал, белки, жиры, углеводы | Значения для поданной порции. Любое из них может быть неизвестно. |
| Происхождение | Введено вручную, оценка по фото (с названием модели), по справочнику, из избранного или бывшая общая оценка приёма. Оценка по фото не выдаётся за измерение. |
| На каких фото | Какие снимки приёма показывают это блюдо. Один снимок может показывать несколько блюд, несколько снимков — одно блюдо. На числа это не влияет. |

## Итог

Итог приёма считает одно место в коде (`MealTotals`): для каждого блюда — значение поданной порции × съеденная доля, затем сумма по каждому показателю отдельно. Неизвестное значение остаётся неизвестным и не считается нулём. Если калории известны не для всех блюд, итог подписан: «известно ≈650 ккал, оценены 2 из 3». Такой частичный итог не используется как калорийность приёма ни в сводке дня, ни в наблюдениях.

Пример: суп 250 ккал, второе 400 ккал, напиток 100 ккал — один приём на 750 ккал. Удаление второго даёт 350 ккал. Ещё одно фото супа итог не меняет.

При сохранении итог записывается в сам приём пищи (масса, ккал, БЖУ и сколько блюд покрывает каждый показатель). Поэтому дневник, хронология, отчёты и наблюдения читают одно и то же значение. Отдельно редактировать этот итог нельзя: он меняется только через блюда.

## Общая оценка приёма

Быстрый ввод и записи прошлых версий остаются в режиме общей оценки: одна масса, калорийность и БЖУ на весь приём. Кнопка «Разбить по блюдам» переводит приём в блюда. Уже введённая общая оценка становится первым блюдом без изменений: она не делится между продуктами и не пересчитывается через «сколько съедено». Обе оценки никогда не складываются. «Сколько съели» у приёма целиком показывается только в режиме общей оценки; в режиме блюд доля задаётся у каждого блюда, поэтому не применяется дважды.

При обновлении базы до версии 3 старые приёмы пищи и избранное сохраняют свою общую оценку и список продуктов. Блюда для них не создаются.

## Напитки к приёму

Калорийный напиток лучше записать напитком и привязать к приёму пищи. Тогда его объём попадёт в жидкость, а калории в итог дня, и посчитаются один раз. Приём пищи показывает такие напитки, но не добавляет их в свой итог. Подробнее: [калории за день](intake.md).

## Распознавание фото

Если в приёме ещё нет чисел, результат распознавания заполняет поля, как раньше, а значения, которые вы изменили во время запроса, сохраняются. Если числа уже есть, результат ничего не заменяет сам. Карточка распознавания предлагает выбрать:

- «Добавить как отдельное блюдо»: новое блюдо со своими числами и этим фото. Прежняя общая оценка, если она была, становится первым блюдом.
- «Это «Суп» с другого ракурса: 250 → 280 ккал»: обновляет выбранное блюдо, сохраняя его название и фото. Изменение видно до применения. Блюда, уже связанные с этим фото, стоят первыми.
- «Заменить общую оценку: 500 → 310 ккал» (только в режиме общей оценки).
- «Не применять».

Ошибка распознавания или удаление одного блюда не трогают остальные.

## Избранное и повтор

Избранное из приёма с блюдами хранит блюда без фото того дня. Выбор такого избранного добавляет его блюда: в новый приём или к уже записанным блюдам («Из избранного» в карточке блюд). «Повторить» копирует блюда приёма с новыми идентификаторами и без фото.

## Резервные копии и экспорт

Блюда хранятся в базе вместе с приёмом и избранным, поэтому входят в резервную копию, восстанавливаются после удаления с отменой и переносятся при восстановлении копии старой версии (база обновляется через миграцию 2→3). В JSON-выгрузке блюда — часть записи приёма. В CSV-архиве есть отдельный файл `meal_dishes.csv`: поданные значения и доля каждого блюда.

## Проверка

`MealTotalsTest` проверяет сумму блюд, удаление блюда, отсутствие влияния фото, неизвестные значения с покрытием и долю съеденного. `MealDishesTest` проверяет редактор:

- три блюда как один приём и удаление блюда;
- второе распознанное фото не заменяет первое молча, а превращает общую оценку в первое блюдо;
- то же блюдо с другого ракурса обновляется, а не удваивается;
- замена общей оценки происходит только по выбору;
- открытие и сохранение приёма с блюдами, отвязка удалённого фото;
- избранное и повтор с блюдами, отмена удаления.

`NutritionMigrationTest` проверяет, что приёмы версии 2 сохраняют общую оценку без выдуманных блюд. `FoodDishesUiTest` в настоящем приложении разбивает приём на три блюда, проверяет частичный итог «известно для 2 из 3» и его подпись в дневнике.
