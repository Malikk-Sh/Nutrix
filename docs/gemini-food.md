# Распознавание еды с Gemini

В редакторе еды прикрепите фото и откройте карточку «Определить еду по фото». Если снимков
несколько, выберите один. Можно уточнить размер порции, тарелки, состав, масло и способ
приготовления. Нажмите «Определить по фото»: во время запроса видны загрузка, номер попытки
и кнопка отмены. Успешный ответ автоматически заполняет название, продукты, массу порции,
ккал и БЖУ в редакторе. Все значения можно исправить вручную. Сохранение записи в дневнике
выполняется обычной кнопкой «Сохранить»; само распознавание запись не сохраняет.
Кнопка «Посмотреть исходную оценку» открывает подробности ответа Gemini без изменения формы.
Правки, внесённые пользователем во время ожидания ответа, сохраняются в соответствующих полях.

Gemini предлагает название, основные продукты, массу съедобной порции, общие ккал и БЖУ.
Значения на 100 г вычисляются из массы и общих значений в приложении. Неизвестное значение
остаётся пустым, а не превращается в ноль. Это оценка по внешнему виду: скрытое масло,
начинка, плотность и масштаб могут существенно менять результат. Для точной массы нужны
кухонные весы. Калории и БЖУ не заменяют фактический состав продукта или данные этикетки.
Вес порции не записывается в дневник веса тела.

## Ключ на телефоне

1. Создайте Gemini API key в [Google AI Studio](https://aistudio.google.com/apikey).
   Используйте актуальный ключ, доступный вашему проекту и региону, с доступом к Gemini API.
2. Откройте **Профиль → Распознавание еды / Настроить Gemini** или ту же кнопку в редакторе еды.
3. Введите и сохраните ключ. Нажмите «Проверить доступ и получить модели»: отправляется запрос
   списка моделей, фото при этом не передаётся и генерация не запускается.
4. По умолчанию используется `gemini-3.1-flash-lite` из прототипа. Можно сохранить другое имя
   мультимодальной модели с поддержкой JSON. Только одна выбранная модель получает запрос.
   Доступность и стоимость зависят от проекта Google. Автоматического перебора моделей нет.
   При сетевом сбое, таймауте или временной ошибке сервиса редактор повторяет запрос один раз
   через 2 секунды. Кнопка отмены останавливает и запрос, и ожидание повтора.
   Ошибки ключа, доступа, квоты, модели и некорректного ответа автоматически не повторяются.
   После ошибки доступна кнопка «Повторить» для нового запроса с выбранным фото и подсказкой.
   Повторы также расходуют квоту API-ключа.

Ключ шифруется существующим Android Keystore/AES-GCM перед сохранением в DataStore. Он не
показывается повторно, не попадает в APK/BuildConfig, Android saved state, резервные копии,
отчёты или логи. В приложении нет встроенного общего ключа. На новом телефоне ключ нужно
ввести отдельно. Настройка ключа для облачной тестовой среды не настраивает ключ в APK.

## Что отправляется Google

Только выбранное фото еды и введённая подсказка, после явного нажатия кнопки. Фото
уменьшается до 1280 px по длинной стороне и заново кодируется в JPEG без EXIF/GPS; предел
подготовленного снимка — 2 МиБ. Остальные фотографии и записи здоровья не включаются
в запрос. Данные Health Connect/Samsung Health не используются для распознавания еды.
Обработка изображения на стороне Google зависит от условий Gemini API и настроек проекта.

HTTPS-адрес в клиенте фиксирован: `generativelanguage.googleapis.com`. Ключ передаётся
в `x-goog-api-key`, не в URL. Редиректы выключены; редактор допускает только один автоматический
повтор временного сбоя, без дополнительных повторов HTTP-клиента. Ответ ограничен
256 КиБ. Отмена прекращает сетевой запрос; поздний ответ для удалённого/изменённого фото
не применяется. Запись не сохраняется во время распознавания. Только успешная проверенная
оценка заполняет редактируемую форму; частичные ответы и ошибки не меняют введённые данные.
Ответы с обрывом, блокировкой, неверными диапазонами или без еды отклоняются.
Сырые ответы с ошибками сервиса не отображаются и не логируются.

## Подготовка среды для проверки агентом

В настройках **подключённой облачной среды**:

- добавьте секрет, передаваемый процессам как `GEMINI_API_KEY`;
- в разрешённых исходящих HTTPS-хостах добавьте `generativelanguage.googleapis.com`;
- сохраните/примените конфигурацию к текущей задаче. После этого сообщите, что среда готова.

Не вставляйте ключ в чат, issue, pull request или GitHub-файл. Агент проверяет только имя и
готовность секрета, затем использует его в запросе без вывода значения. Изменение локального
`/etc/codex/network-policy.json` не даёт сетевого доступа; разрешение хоста задаётся через
конфигурацию среды. Proxy и проверка TLS остаются включёнными.

В этой рабочей среде подготовлен `.venv-gemini` (не отслеживается Git). Повторная подготовка:

```bash
bash tools/setup-gemini-test-env.sh
```

Проверка доступа без фото:

```bash
.venv-gemini/bin/python tools/gemini_food.py --check
```

Один реальный запрос с явно выбранным тестовым фото:

```bash
.venv-gemini/bin/python tools/gemini_food.py \
  --image /absolute/path/food.jpg \
  --hint 'Тарелка 25 см, курица без кожи, одна ложка масла' \
  --model gemini-3.1-flash-lite
```

Подготовка фото и JSON без сети, ключа и расходования квоты:

```bash
.venv-gemini/bin/python tools/gemini_food.py --dry-run --image /absolute/path/food.jpg
```

Для самостоятельного запуска в локальном Bash можно ввести ключ без отображения и записи
в историю команды (экспорт действует только в этом терминале и его дочерних процессах):

```bash
read -rsp 'Gemini API key: ' GEMINI_API_KEY
export GEMINI_API_KEY
printf '\n'
.venv-gemini/bin/python tools/gemini_food.py --check
unset GEMINI_API_KEY
```

JSON формируется сериализатором: кавычки и переводы строк в подсказке не ломают запрос.
CLI использует ту же JSON-схему и системную инструкцию из Android assets. Он не сохраняет
ключ, исходный запрос с base64-фото или сырой ответ на диск. `GEMINI_MODEL` может задавать
модель для CLI; ключ для него читается только из `GEMINI_API_KEY`.

## Хранение и совместимость

БЖУ и происхождение оценки сохраняются в nullable JSON-колонке `nutrition` таблиц `meals` и
`favorite_meals`. Вес порции и ккал остаются в прежних полях. Избранное, повтор блюда,
редактирование, черновики, JSON/CSV-экспорт и резервные копии сохраняют нутриенты. Изменения
формы автоматически заполняются после успешного ответа и попадают в черновик. Сохранение
дневника выполняется отдельной кнопкой; просмотр исходной оценки не меняет форму.

Room мигрирует схему 1 → 2 двумя `ALTER TABLE`, без удаления записей. Старые резервные копии
проверяются на отдельной временной копии базы, чтобы миграция Room не меняла проверенные
SHA-256 исходного архива. При восстановлении старая база мигрируется в устойчивом staging
до переключения живых данных. Ключ устройства при восстановлении не заменяется ключом из
архива. Старое приложение со схемой 1 не сможет открыть новую копию со схемой 2.

## Проверки

```bash
./gradlew testDebugUnitTest lintDebug
.venv-gemini/bin/python -m unittest discover -s tools/tests
```

HTTP-тесты используют локальный MockWebServer, UI-тест — подставной анализатор. Проверяются
сериализация подсказки, заголовок ключа, отсутствие редиректов и скрытых повторов HTTP-клиента, ошибки и отмена,
ограничение ответа, загрузка, один повтор временного сбоя, отмена ожидания повтора,
ручной повтор после ошибки, автоматическое заполнение, ручные правки, БЖУ, EXIF, миграция старой базы и
восстановление старых копий. CI никогда не требует API-ключа и не посылает фотографии Google.
Реальный сетевой запрос запускается только явно указанной выше командой после подключения
секрета и разрешения хоста. Успешные тесты с подставными ответами не подтверждают качество
определения продуктов или численную точность Gemini на конкретном снимке.

Официальные источники: [generateContent](https://ai.google.dev/api/generate-content),
[JSON-схемы](https://ai.google.dev/gemini-api/docs/structured-output),
[работа с изображениями](https://ai.google.dev/gemini-api/docs/image-understanding),
[ключи API](https://ai.google.dev/gemini-api/docs/api-key).
